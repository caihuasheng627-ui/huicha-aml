# 循证慧查 BP v4.5.6 审查意见（Grok 4.7 high）

审查身份：工行杯国奖评委（银行合规/反洗钱业务 + 材料统稿）。只审计划书，不改产品代码。

材料：`uploads/bp_v456_fulltext_for_review.md`（v4.5.6 全文抽取）、`uploads/bp_v456_notes.md`（本轮仅改六（一）截图链，§七 41 段与 v4.5.5 相同）。对照仓库已有口径：`huicha-aml/experiments/RESULTS.md`、`experiments/REAL_MODEL_REPORT.md`、`backend/app/prompts.py`（`prompt_version` 返回 `judge_v3p`）、`答辩作战手册.md`。docx 本体不在本仓库，超链接是否仍可点击以抽取可见文字为准。

硬口径（下列改法均不得违反）：告警后调查 Copilot，不改成监测引擎；规则与 AI 不相加；人双控签发；不自动报送；证据闸门保留；合成对照保持为合成对照；不新编团队实名、奖项、真实银行流水或新实验数字；§七已有数字不得上调。

## 总评

机制章已经能打国奖。卡位、四条分工、代码闸门、双控与「已签草稿仍不报送」，以及§七把 stub 全流水线、真模型直调消融、产品默认 `judge_v3p` 拆开，都是评委追问时站得住的写法。v4.5.6 把案例 `20260910-L` 的真模型截图补进六（一），方向对。

现在拉开名次的不是再写高一个 F1，而是三件评委翻页就能抓住的事：图号表号和团队表与正文互不对齐；九步截图链和「控误报」三字会把作品听成「监测降误报」或「闸门要开实验模式才生效」；背景罚没数据和参考文献不可当场核验。商业章（八、九、十）对同一卡位重复多遍，90 日工行样板没有机制验收，市场空间没有出处。国奖银行评委会在这里扣「落地是否可验收」，不会因为 PEST 写得更满而加分。

处理原则：统稿、防误读、把工行 90 日收成可演示的验收。数字只许原样转引仓库已有结果，或删掉无法闭合的形容词。不要补一版新的准确率，不要把 `judge_v3p` 说成已经有独立主表。
