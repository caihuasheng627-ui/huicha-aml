## A. 产品定位与赛道叙事

### 现状

定位句已经写进 README、作品报告、作战手册、health `contest.headline`，口径一致：

> 上游监测已经产生告警。循证慧查不替代检测，只把「告警 → 调查 → 报告」交给受控 Agent 出初稿，人只做确认、修改或驳回。

赛道桥也已钉死：调查提效服务追赃窗口，**仓库没有追赃时效实测**。与监测类作品的切割句可用：「他们回答疑不疑；我们回答为什么、证据在哪、报告怎么写。」

代码与叙事匹配的主路径：告警升级为 Case → 只读取证 → 规则对照与 AI Judge **并排不相加** → 护栏 → 四段底稿 → **人签，状态不是已报送**。

### 风险

- 技术文档 / 作品报告仍有 **V2 残留措辞**（「打分拆解」「采纳/修改后采纳/驳回」），和现网「提交复核 / 同意签发」不一致，评委对照屏幕会问。
- 知识库 playbook `KB-PROC-01` 仍写「Challenger 必须尝试经营抗辩」，而 V3 已不再走调分 Challenger。
- 若 PPT 把作品画成检测模型或「已缩短追赃时间」，直接撞红线。

### 应做

- PPT 第 1–2 页只保留：定位句、赛道桥、灰/蓝分段（监测 / 调查）。
- 商业计划从技术文档摘句时，以作战手册禁语表为准，冲突先改那一页。

### 优先级

**P0** 上场材料去旧句；**P1** 技术文档/作品报告把处置动作改成双控用词。

## C. 隐私与安全

### 现状

| 项 | 实现 | 诚实写法 |
|----|------|----------|
| `privacy_v2` | **有**。工作台与签发稿受控明文；**只有 LLM 出站**走 PrivacyMap（姓名→`CLIENT_001`，账号→`ACCOUNT_001`，客户号→`CUST_001`）。`TX-*` 不替换。 | 「进模脱敏，不是数据不出域」 |
| 出站检漏 | `prepare_for_llm` 后 `assert_clean`；`chat()` 再拦 `6222-` 形态；命中则中止调查。 | 「漏脱敏不发模型」 |
| 工具白名单 | 见 B。 | 「Agent 无写核心、无报送工具」 |
| CORS | 默认仅本地 Vite 源，**不是** `*`。 | 竞赛本机即可 |
| 演示口令 | `HUICHA_DEMO_TOKEN` 为空则**读接口开放**；填写后需 `X-Huicha-Token`。签发/导出始终要登录会话。 | 「竞赛口令，不是银行登录」 |
| 存储加密 | **无**。SQLite `huicha.db` 调查载荷明文。 | 文档已承认 |
| SSO / 岗位 IAM | **无**。内存 session + 两枚演示工号。 | 文档已承认 |

### 风险

- 评委把「进模脱敏」听成「银行级加密 / 数据不出域」。
- 默认读接口开放，若现场投屏或共享端口，告警列表可未登录读取（签发仍需登录）。
- 演示口令写在仓库与说明书里，只适用于竞赛，不得写进对外「已合规」。

### 应做

- 红队第 15 题第一句已写好，答疑照念。
- 比赛机可不设 `HUICHA_DEMO_TOKEN`（少一步）；若设了，登录框要填接口口令。
- 生产方案只作为**未做**：模型不出域或行内私有化。不要画成已上线。

### 优先级

**P0** 口径；加密/SSO 属落地（H），竞赛期 **P2** 不实现。

## D. 实验与评测诚实口径

### 现状（同意现有诚实口径）

1. **Stub 机制验证**（`python -m app.experiments`）：毒化草稿 n=200 拦截 100%；干净文本误报 0%；模板精标 n=87，Judge↔规则分歧 40.2%；引用契约 100%。**不是准确率**，Judge 为 stub，金标与规则同源。
2. **独立合成集真实模型**：产品路径 `enrich_judge → normalize → verify → guardrails`。主集 n=240，11 叙事族。`judge_v2` Macro-F1 ~0.39 → `judge_v3` ~0.97，排除档不再全灭。盲区集 keyword ~0.11，说明不只是词面匹配。**合成金标，不是生产准确率，须人签。**
3. **`judge_v4`**：仅消融。切默认的条件（三套 hold-out 均不低于 v3 且观察族偏严减少）**未满足**（结构盲区上官方 DeepSeek 的 v4 不优于 v3；百炼结构盲区 v4 曾欠费中断）。默认必须保持 `judge_v3`。
4. **人效**：`HUMAN_STUDY.md` 协议完整；`efficiency_records.csv` **仅表头**；`efficiency.py` 空表拒绝计算提升百分比，有样本也**禁止输出百分比**（单测锁定）。
5. **外部盲评**：`gold_review_labels.json` 是实验作者自洽，**不得**写成外部一致率。`gold_review_labels.external.json` 不存在。
6. **真实脱敏 hold-out**：`real_holdout.json` 为 placeholder，明确不进 RESULTS 主表。README 仍写 TODO。

### 风险（本维最大）

- **`RESULTS.md` 结构危险**：文件被多次追加，出现多张「同一独立集」消融表；文首「独立集 / 真实模型」块的 `prompt=judge_v4`、Macro-F1 **0.994**（盲区集）。有人会把 0.994 当成产品成绩。产品默认是 `judge_v3`，主集约 **0.97**，且 REAL_MODEL_REPORT 已写明：例举词覆盖上报族，0.97 是乐观估计。
- `RESULTS.json` 的 `independent_real_model` 槽位是「最近一次跑」，目前指向 blind × `judge_v4`，不是产品默认。
- 主集 keyword 基线约 0.80、盲区约 0.11：说明主集词面可打，**不要**在主集上夸「远超关键词」。
- v2 集已作废，不得与 v3 混比（作战手册红队 19 已覆盖）。

### 应做

- 现场**不要念** Macro-F1 裸数字。允许句见作战手册 §4。
- 计划书效果章只保留：机制验证（正则拦截）+ 「v3 相对 v2 消除默认观察偏置」+ 「须人签」。
- 人效：能做教室对照更好（P1）；**做不完就保持空表，绝不填编造 %**。
- 有空再整理 RESULTS.md 只留「现行有效」一张主表 + 历史附录（P1，不改数字）。

### 优先级

**P0** 禁语与抄对默认 prompt；**P1** 整理 RESULTS 版面、教室人效、外部一人盲评；**P2** 真实 hold-out（无脱敏行内数据则保持 TODO）。
